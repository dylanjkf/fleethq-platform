# FleetHQ — Overview

## Purpose
The web console for everyone who isn't in an asset: dispatchers, workshop managers, compliance officers, and business owners/managers. One login, permission-scoped views into dispatch, workshop, compliance, reporting, and administration.

## Core areas
- **Home** — role-adapted landing view answering "what needs my attention today," per Product Philosophy's "build around the workday."
- **Dispatch** (`05-Dispatch/`)
- **Workshop** (`06-Workshop/`)
- **Compliance** (`08-Compliance/`)
- **Fleet Registry** — asset, attached unit, operator, customer, depot records and their Timelines/Digital Gloveboxes.
- **Reporting** — cost trends, uptime, fuel, compliance status, exportable and scheduled.
- **Administration** — users, roles/permissions, company settings, multi-company management, Universal Forms builder.
- **Universal Search / Command Bar** — available globally, per `01-Product/Universal_Search.md`.

## Requirements
- Every screen respects the requesting user's permissions exactly — no area is visible-but-disabled; ungranted areas are simply absent from navigation.
- Role-adapted home view: a Compliance Officer's home surfaces compliance risk; an Operations Manager's home surfaces today's costs and exceptions — same platform, different default lens, configurable per role template.
- Fully responsive for desktop/laptop use (FleetHQ is not designed primarily for a phone-sized screen — that's DriverOS's job).

## Edge cases
- A user with permissions spanning multiple areas (e.g. a small courier company owner who is also the dispatcher and the admin) should get a coherent combined home view, not a jarring "pick a persona" experience — role-adapted home views should compose, not force a single choice.

## Technical considerations
- FleetHQ is a client of the same API every other client uses (`12-API/API_Architecture.md`) — no FleetHQ-only backend shortcuts.

## Acceptance criteria
- A new company admin can create users, assign roles, and see their fleet's Dispatch/Workshop/Compliance state within the "10 minutes to first value" bar set in `Mission.md`.

## Future expansion notes
- Deeper analytics/BI-style reporting is a natural place for the platform to grow once core operational usage is established.

## Implementation notes
- The API side of the Administration area's "users, roles/permissions, company settings" is built (`apps/api`'s Administration API milestone — signup, user invite/role-change/deactivate, role CRUD/clone/archive).
- **FleetHQ v1 foundation is now built** (`apps/fleethq` — Vite + React 19 + TypeScript + TanStack Query + React Router v7 + Tailwind v4 + Radix UI). Live, working, permission-aware pages: Dashboard (widget-grid: Fleet/Operators/Users counts, System Health via `/health/ready`, placeholder widgets for Fleet Health Score/Upcoming Maintenance/Recent Activity/Fleet Graph), Fleet (Assets + Attached Units, as permission-gated tabs), Operators (CRUD), Administration (Company/Users/Roles as permission-gated tabs), Profile, Settings (appearance + notification-preferences shell). Auth flow (login, multi-company selection, session persistence via `GET /v1/auth/me`) is fully wired. Navigation shows every module named in the brief; **Reports and Universal Forms are now real pages** (see their own implementation notes below and in `01-Product/Universal_Forms.md`) — only Documents, Knowledge Base, and AI remain `ComingSoonPage`, matching this doc's "no area is visible-but-disabled" rule for *built* areas while keeping unbuilt areas honestly labeled.
- **Dispatch is now a real page** (Dispatch milestone): job creation, assignment to an Asset/Operator, and status (Unassigned/Assigned/Completed/Cancelled) — see `05-Dispatch/Dispatch_Overview.md`'s implementation notes for the full scope and what's deliberately still not built (live map, GPS, route optimization, chat).
- **Maintenance is now a real page** (Workshop milestone): manual job logging, a linear status lifecycle, approval, and closing with resolution notes — see `06-Workshop/Workshop_Overview.md`'s implementation notes. Its severity flag now surfaces directly in the Dispatch assign dialog, per Dispatch's own acceptance criterion.
- **Multi-company management is no longer limited to the login-time switcher**: the Administration Users tab now has a "Link existing user" action (`POST /v1/users/link`) granting an existing login access to a second company under a chosen role — verified end-to-end with one login gaining access to two companies with different roles in each.
- **Compliance is now a real page** (Compliance milestone): per-asset registration/insurance/roadworthy document logging, with a derived expiry status (Valid/Expiring Soon/Expired) sorted soonest-first — see `08-Compliance/Australian_Compliance.md`'s implementation notes for the full scoped-down slice (no fatigue tracking, no NHVR/CoR rule engine).
- **Bulk CSV import is now live** (Import milestone): both the Fleet page's Assets tab and the Operators page have an "Import CSV" action (upload → map columns → dry-run preview → commit), gated on the same `assets:create`/`operators:create` permissions manual creation uses — see `01-Product/Onboarding_Import.md`'s implementation notes.
- **The Dashboard's Fleet Health Score placeholder is now real** (Fleet Health Score milestone): an average score and at-risk count on the Dashboard, linking through to a full `/fleet-health` breakdown page (every asset, sorted worst-first, with an explainable factor breakdown) — see `01-Product/Fleet_Health_Score.md`'s implementation notes for the scoped-down slice (Maintenance + Compliance factors only) and why it deliberately has no sidebar nav entry (same precedent as Fleet Graph).
- **Verified permission-aware navigation end-to-end**: created a zero-permission test role/user via the live Administration UI and confirmed nav items, dashboard widgets, and a direct URL visit to `/administration` are all correctly hidden/redirected — not just filtered in the sidebar.
- **Operators tab now has a "Link login" action** (DriverOS v0 milestone): a new "DriverOS" column shows whether an Operator has a linked login ("Linked"/"No login"), and a row action (gated on `users:create`, hidden once already linked) opens a dialog to grant one (username/password/role), reusing the Operator's existing `fullName`. This is what makes an Operator record login-capable for the new `apps/driveros` client — see `04-DriverOS/DriverOS_Overview.md`'s implementation notes for the full design.
- **The Fleet page's Asset form now has an Emergency contact field** (Digital Glovebox milestone): a single free-text field feeding DriverOS's new Digital Glovebox screen — see `01-Product/Digital_Glovebox.md`'s implementation notes for the full scoped-down slice.
- The permission catalog is duplicated in `apps/fleethq/src/lib/permissions.ts` rather than imported from `apps/api`, since the two are separate deployables with no shared package yet. Revisit if/when the two catalogs actually drift (Tier 1 item, see the FleetOS Memory Vault Decision Log).
- **Reporting depth (`17-Roadmap/Product_Roadmap.md`'s v1.x line)**: the Reports page's operational reporting slice now also surfaces **maintenance cost trend** (a per-day cost chart plus total/average, from `MaintenanceJob.partsCost`/`laborCost` captured on close — see `06-Workshop/Workshop_Overview.md`'s implementation notes) and **fleet uptime** (a fleet-wide uptime % plus a worst-first per-asset downtime table, computed from time spent with an open CRITICAL maintenance job — the same severity this codebase already treats as work-blocking elsewhere, e.g. Dispatch's assign warning and Operational Recommendations' scoring). Both are pure computation over existing rows, gated on the existing `reports:view` permission — no new permission, no new stored aggregate. No charting library was added; the cost trend is a small dependency-free bar chart (plain divs), consistent with this app having no chart library anywhere else.
- **The three "coming soon" dashboard widgets are now live**: **Upcoming Maintenance** (overdue/due-soon counts + the next few due plans, each linking to its asset, from `GET /v1/maintenance-schedules/plans`), **Recent Activity** (a company-wide cross-entity feed from the new `GET /v1/timeline/recent`, `timeline:view`), and **Fleet Graph** (a roll-up from the new `GET /v1/graph/summary` — live-link count, linked assets/operators, breakdown by relationship type, most-connected assets, `fleet_graph:view`). Each widget gates its own query on the relevant permission and degrades gracefully. The `PlaceholderWidget` component was removed.
- **Dashboard "morning operations view" widgets** (Wave K): four more reorderable, permission-gated grid widgets, every figure derived from live rows (no hardcoded/placeholder numbers). **Operations snapshot** — Assets active · In workshop · Services due · Open defects from `GET /v1/dashboard/metrics` (in-workshop = assets with an open maintenance job, the honest proxy for "off road" since Asset has no status field; open defects = driver-raised open jobs; services due folded into the same endpoint). Each tile carries a real "vs yesterday" delta chip (current value − the most recent prior-day snapshot average, from the extended `utilisation_snapshots` row), coloured by whether the move is good news; the delta is null (no chip) until a prior day is recorded, never a fabricated baseline. **Compliance position** — document currency (valid/expiring/expired) from `GET /v1/compliance-documents/summary` + today's pre-start completion from `GET /v1/checklist-status/today`, as `MeterBar` progress bars. **Expiring soon** — the next compliance documents to lapse (existing expiry-ordered list, days-remaining derived). **Fleet utilisation** — a live point-in-time gauge (assets on an ASSIGNED job ÷ active assets) plus a real accumulated day-by-day trend: a new `utilisation_snapshots` table (one accumulating row per company per day) that the leader-elected scheduler folds the current reading into each tick, served by `GET /v1/dashboard/utilisation-trend` and drawn as a dependency-free SVG sparkline beneath the gauge — genuine history, never a fabricated back-fill (a new company's trend fills in over the coming days). Widget keys added to the backend catalog (`dashboard-widgets.ts`) + the `nodes` map; the richer panels span extra grid columns.
- **Analytics controls** (Wave L, `analytics:manage` — Administration → Analytics tab): a company can adjust or reset the dashboard percentages. Four controls, all kept honest (overrides are marked "Manually adjusted" on the dashboard and every change is `AuditService`-logged): set targets/thresholds (`analytics_settings`; the utilisation target draws a dashed guide line on the sparkline, thresholds colour the compliance bars), manually override a live figure (`analytics_overrides`, one per company+metric — utilisation / compliance-current / pre-start), exclude an unrepresentative day from the trend/delta (an `excluded` flag on the snapshot — a correction to inputs, not the output), and reset accumulated history (clears `utilisation_snapshots`). `/v1/analytics/*`: reads gated `assets:view` so the widgets consume targets/overrides, all writes `analytics:manage`.
- **Impact page** (`/impact`, `reports:view`) answers "how beneficial has FleetOS been for the company" with a benefit story rather than raw ops numbers: `GET /v1/reports/impact` returns a monthly series (deliveries delivered/failed, delivery + on-time rates, pre-start checks, maintenance cost) plus headline totals since first activity (deliveries proven, on-time %, checks completed & clean-pass %, faults tracked to closure, maintenance cost tracked, fleet under management). Rendered with dependency-free, theme-aware SVG charts (stacked bars + a multi-line percentage trend) and a CSV export — still no charting library.
- **Australian vehicle quick-fill on the Asset form**: a Make → Model → Year picker (`features/assets/australian-vehicles.ts`) speeds up adding a vehicle by populating the free-text make/model/year fields from a broad catalogue of makes/models available on Australian roads (courier vans/utes/light-and-heavy trucks first, mainstream passenger too). The list is deliberately broad rather than VIN-exhaustive; every field stays free-text so anything not listed can still be typed. Asset names already linked to the `/fleet/:assetId` detail page.
- **Self-serve signup + free trial + plan picker (sell-readiness pass).** `/signup` (public) creates a company + admin via `POST /v1/companies` and logs them straight in on a **7-day** native free trial (`Company.trialEndsAt`, length from `TRIAL_PERIOD_DAYS`; `TRIAL_TIER` grants every feature during the window, then Free). A persistent AppShell trial banner and a Billing-page countdown drive conversion. Billing sells the **per-asset plan — $9/asset/month** (`STRIPE_PRICE_PER_ASSET`, the asset count set as the subscription quantity), via `GET /v1/billing/plans`, instead of one hardcoded price. Login links to signup and back.
- **Branded 404s + first-run guidance.** Both apps have a catch-all `*` route rendering a branded not-found page. The Fleet/Operators/Dispatch empty states now carry a first-action CTA (add asset / add operator / create run) so a brand-new company always has an obvious next step.
